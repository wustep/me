## Technical

### 1. Lock down `/api/search-notion`, which is live even though search is disabled

- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `site.config.ts` sets `isSearchEnabled: false`, so no UI calls the route, but `pages/api/search-notion.ts` forwards the raw `req.body` to `notion.search()`. Callers control `ancestorId`, `limit` and `filters` (see `notion-client` `search`), so the site can be used as a proxy to search any public workspace. With `NOTION_TOKEN_V2` set, that search runs as a logged-in user. Each distinct body also creates a new entry in the 60s memo cache in `lib/notion.ts`.
- **Proposal.** Return 404 when `!config.isSearchEnabled`. Otherwise accept only a string `query` (≤200 chars), pin `ancestorId` to the site root on the server, cap `limit`, and drop client `filters`. Put the validation in a pure `lib/` helper with unit tests.
- **Risks / trade-offs.** Nothing calls the route today. react-notion-x only sends `{query, ancestorId}`, so re-enabling search still works.
- **Files.** `pages/api/search-notion.ts`, `lib/search-params.ts` (new), `lib/__tests__/search-params.test.ts` (new)

### 2. Collection dates can render the previous month and differ between server and client

- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `components/NotionPage.tsx` list-view date override parses `new Date('2016-12-01')` as UTC midnight, then reads the month and year in local time. Vercel prerenders in UTC and gets "Dec 2016"; a US browser renders "Nov 2016". The result is a wrong date plus a hydration text mismatch on any 1st-of-month date. `notion-utils` `formatDate`, used for the header dates, has the same local/UTC mix.
- **Proposal.** Add `lib/format-date.ts` (`formatMonthYear`, `formatLongDate`), with every part computed in `timeZone: 'UTC'`, and use it in the three overrides. Unit-test 1st-of-month and year-boundary dates under `TZ=America/Los_Angeles`.
- **Risks / trade-offs.** Timed dates would render in UTC, which matches what the server already outputs.
- **Files.** `components/NotionPage.tsx`, `lib/format-date.ts` (new), `lib/__tests__/format-date.test.ts` (new)

### 3. Every LLM lens deck page bundles all five decks' data

- **Impact:** 🔴 high · **Effort:** M · **Status:** ❌ rejected
- **Problem.** `components/wustep/lenses/llms/decks.ts` imports all five `lenses.json` files (~360 KB raw) and builds each deck at module load. Every `/lenses/llms/<slug>` page therefore ships every deck, plus the original deck and the 83 KB `illustrations.tsx` via `deck.tsx`.
- **Proposal.** Use one module per deck, generate a small directory summary for `LlmsDirectory`, and move the default `WUSTEP_DECK` out of the shared context module. Measure First Load JS per route before and after.
- **Risks / trade-offs.** The `llm-lens-deck` skill and `sync-lenses.mjs` assume the current layout and need updating. Each new deck adds one more file.
- **Files.** `components/wustep/lenses/llms/decks.ts`, `pages/lenses/llms/**`, `components/wustep/lenses/deck.tsx`, `LlmsDirectory.tsx`, `scripts/sync-lenses.mjs`

### 4. `/` and `/playground` bundle all 29 lens illustrations to draw one

- **Impact:** 🟡 med · **Effort:** S · **Status:** ❌ rejected
- **Problem.** `AboutPage.tsx`, `LensesCover.tsx` and `LensesIllustrationLabCover.tsx` render only `<Illustration id='lenses-deck'>`. `Illustration` is a `switch` over every `Art*` component in the 2,493-line `illustrations.tsx`, and a switch like that can't be tree-shaken.
- **Proposal.** Move `ArtLensesDeck` and the shared SVG constants into their own modules and import them directly from those three components. `Illustration` re-exports them so the deck still works.
- **Risks / trade-offs.** It's a pure move, so minimal. Check the other ids used by the Lab cover first.
- **Files.** `components/wustep/lenses/illustrations.tsx`, `components/AboutPage.tsx`, `components/wustep/LensesCover.tsx`, `components/wustep/LensesIllustrationLabCover.tsx`

### 5. The override slug map caches partial Notion failures for 25 minutes

- **Impact:** 🟡 med · **Effort:** S · **Status:** ❌ rejected
- **Problem.** `lib/posts-collection.ts` fetches six override pages with `Promise.all` through the raw client and logs and ignores any failure. It then memoizes the partial map for `SLUG_MAP_TTL_MS` (25 min), so a single 429 leaves hidden-post slugs returning 404 and missing from RSS.
- **Proposal.** Return `{ map, complete }` and only cache complete results (or give partial ones a short TTL). Fetch with `pMap` at concurrency 2. Add a test where one page fails.
- **Risks / trade-offs.** More Notion calls while Notion is flaky.
- **Files.** `lib/posts-collection.ts`, `lib/__tests__/posts-collection.test.ts`

## UI/UX & Design

### 6. Full-frame Playground pages: no loading state, no page heading

- **Impact:** 🔴 high · **Effort:** M · **Status:** ❌ rejected
- **Problem.** Only `bookshelf.tsx` and `starry-sequencer.tsx` handle iframe loading. The other iframe demos show a blank frame until the remote app boots. `PlaygroundLayout.tsx` renders `<h1>` only when not `fullFrame`, so full-frame toys have no h1. Iframe titles are inconsistent ("Spot it! iframe", "DOMino iframe").
- **Proposal.** Add a shared `<PlaygroundFrame>` with an `onLoad` status overlay and a timeout fallback ("open in its own tab"). Render an `sr-only` h1 for full-frame pages, and standardize the iframe titles.
- **Risks / trade-offs.** Cross-origin `onLoad` timing is unreliable, so keep the timeout.
- **Files.** `components/wustep/PlaygroundLayout.tsx`, `pages/playground/*.tsx`, `components/wustep/PlaygroundFrame.tsx` (new)

### 7. Muted text in the prompting presentation fails AA on both slide backgrounds

- **Impact:** 🔴 high · **Effort:** S · **Status:** ❌ rejected
- **Problem.** `PromptingPresentation.module.css` `--muted: #7c7064` is roughly 3.9:1 on `.slideDark` and 4.2:1 on `.slidePaper` (estimated). It's used for 14 body-text selectors plus 8px SVG labels.
- **Proposal.** Split the token into on-dark and on-paper variants that each clear 4.5:1, and raise the chart labels to ≥11px.
- **Risks / trade-offs.** Small visual change to a tuned palette.
- **Files.** `components/wustep/prompting/PromptingPresentation.module.css`

### 8. Add a skip link and mark the current Playground page with `aria-current`

- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** There's no "skip to content" link anywhere. Keyboard users tab through the full header or the 15+ entry Playground sidebar before reaching content. `PlaygroundSidebar.tsx` passes `isActive`, which only sets `data-active`; unlike `PromptingLayout.tsx`, it never sets `aria-current='page'`.
- **Proposal.** Add a global visually hidden skip link that becomes visible on focus, target `#main` on the Notion and Playground content, and add `aria-current` on the active sidebar link.
- **Risks / trade-offs.** Each layout needs a stable `id='main'`; surfaces without one just skip nothing.
- **Files.** `pages/_app.tsx`, `components/NotionPage.tsx`, `components/wustep/PlaygroundLayout.tsx`, `components/wustep/PlaygroundSidebar.tsx`, `styles/wustep.css`

### 9. Theme and owner-mode toggles announce contradictory labels

- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `ThemeToggle.tsx` pairs an action label ("Switch to light mode") with `aria-pressed={isDark}`, so screen readers hear "Switch to light mode, toggle button, pressed". `OwnerModeToggle.tsx` does the same.
- **Proposal.** Use a fixed state label ("Dark mode", "Owner mode") with `aria-pressed`, and keep the action wording in `title`.
- **Risks / trade-offs.** None meaningful.
- **Files.** `components/wustep/ThemeToggle.tsx`, `components/wustep/OwnerModeToggle.tsx`

### 10. 404 and error pages: vague tab title, no retry, no next move

- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `Page404.tsx` title is `site?.name || 'Page Not Found'`, so the tab reads just "Stephen Wu". The arrow SVGs aren't `aria-hidden`. `ErrorPage.tsx` has no "Try again", and "We're looking into it" claims monitoring the site doesn't have. Neither page points anywhere useful.
- **Proposal.** Title "Page not found · Stephen Wu", `aria-hidden` on the SVGs, a "Try again" (reload) on the error page with honest copy, and a short "maybe you were looking for" row (Playground / Lenses).
- **Risks / trade-offs.** Keep the AgentOnly llms.txt affordance intact.
- **Files.** `components/Page404.tsx`, `components/Page404.module.css`, `components/ErrorPage.tsx`

## Product Features

### 11. Branded per-lens OG images

- **Impact:** 🔴 high · **Effort:** M · **Status:** ✅ accepted
- **Problem.** `pages/lenses/[lensId].tsx`, `pages/lenses.tsx` and `DeckHead` in `llms/deckPages.tsx` all use `favicon-512x512.png` with `twitter:card=summary`, so shared lens links preview as a favicon. Each lens has `bg`/`fg`/`accent`, a title and a tagline that go unused. `pages/api/social-image.tsx` depends on Notion and can't render lenses.
- **Proposal.** Add a `next/og` edge route, `pages/api/lens-image.tsx?deck=&id=`, that draws a 1200×630 card in the lens colors (title, tagline, wordmark). Point `og:image` / `twitter:image` at it and switch to `summary_large_image`.
- **Risks / trade-offs.** SVG illustrations likely won't render in Satori, so start with text and color only. Keep the edge bundle small by importing JSON only.
- **Files.** `pages/api/lens-image.tsx` (new), `pages/lenses/[lensId].tsx`, `pages/lenses.tsx`, `components/wustep/lenses/llms/deckPages.tsx`

### 12. Put lens content in server HTML so each `/lenses/<id>` has crawlable text

- **Impact:** 🔴 high · **Effort:** M · **Status:** ❌ rejected
- **Problem.** `/lenses/<id>` prerenders only the canvas; the lens opens client-side after `router.isReady`. `getStaticProps` passes only the title and tagline, so crawlers, no-JS readers and unfurlers get no body text.
- **Proposal.** Add a visually hidden `<article>` with the title, body, readings and related links, plus JSON-LD and a meta description from the body's first sentence.
- **Risks / trade-offs.** Duplicated DOM content. The Radix portal can't SSR, which is why this uses a hidden article.
- **Files.** `pages/lenses/[lensId].tsx`, `components/wustep/lenses/LensesPage.tsx`, `components/wustep/lenses/llms/deckPages.tsx`

### 13. Add Lenses and Playground to sitemap.xml, llms.txt and the markdown views

- **Impact:** 🔴 high · **Effort:** S · **Status:** ❌ rejected
- **Problem.** `public/sitemap.xml` lists only Notion slugs. In `lib/agent-content.ts`, `getLensesMarkdown()` and `getPlaygroundMarkdown()` are two-line stubs, so agents requesting `/lenses` as markdown get no lenses.
- **Proposal.** Emit lens, deck and playground routes into the generated sitemap. List every lens (title, tagline, link) in the lenses markdown and llms.txt. Add tests.
- **Risks / trade-offs.** `agent-content` bundles grow by the size of the lens JSON.
- **Files.** `notion-index.config.ts`, `public/sitemap.xml`, `lib/agent-content.ts`, `lib/__tests__/agent-content.test.ts`, `playground/registry.tsx`

### 14. Titles, descriptions and OG metadata for Playground entries, driven by the registry

- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** Of the 16 `pages/playground/*.tsx`, only `contraptions.tsx` sets `og:image`, and 13 have no `<Head>` at all. Shared demo links get the generic site title and no preview, even though `playground/registry.tsx` already has a title and description per entry and `public/playground/covers/*.png` exist.
- **Proposal.** Have `PlaygroundLayout` look up the current path in the registry and emit the title, description, canonical, `og:image` (from the registry image) and twitter card. Remove the one-off block in `contraptions.tsx`.
- **Risks / trade-offs.** Entries with only SVG or animated covers fall back to the default image.
- **Files.** `components/wustep/PlaygroundLayout.tsx`, `playground/registry.tsx`, `pages/playground/contraptions.tsx`

### 15. Previous/next navigation between Playground entries

- **Impact:** 🟡 med · **Effort:** S · **Status:** ❌ rejected
- **Problem.** Full-frame demos offer no next step unless the sidebar is open, and it's often collapsed or hidden on mobile. That cuts against PRODUCT.md's "clear next move".
- **Proposal.** Derive prev/next from the flattened registry (respecting `ownerOnly` / `disabled`). Add compact ← / → buttons in the layout header and `[` / `]` shortcuts.
- **Risks / trade-offs.** Shortcuts don't fire while an iframe has focus. Header crowding on mobile.
- **Files.** `components/wustep/PlaygroundLayout.tsx`, `playground/registry.tsx`, `components/wustep/PlaygroundSidebar.tsx`

## DevEx

### 16. Unit-test owner-mode auth

- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `lib/owner-mode-server.ts` (HMAC session token, minimum secret length, `timingSafeEqual`, `Secure` only in production) has no tests. Regressions in auth would be silent.
- **Proposal.** Add `lib/__tests__/owner-mode-server.test.ts` using `vi.stubEnv`. Cover: an unset or short secret, the round trip, a tampered cookie, and the `Secure` flag appearing only in production.
- **Risks / trade-offs.** None.
- **Files.** `lib/__tests__/owner-mode-server.test.ts` (new)

- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `.github/workflows/build.yml` only diffs `components/wustep/lenses/lenses.json`, but `scripts/sync-lenses.mjs` regenerates all five `llms/*/lenses.json` too. Model-deck drift passes CI. AGENTS.md and contributing.md mention only the one file.
- **Proposal.** Fail on any change under `components/wustep/lenses/` after `pnpm lenses:sync`, and update the wording in both docs.
- **Risks / trade-offs.** The first run could surface existing drift; the check currently passes locally.
- **Files.** `.github/workflows/build.yml`, `AGENTS.md`, `contributing.md`
